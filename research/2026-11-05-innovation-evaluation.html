  • hx-brain: an Obsidian/Markdown wiki and chat-history importer. The QMD hybrid search is documented in the second-brain skill.

1 · BGE-M3 / FlagEmbedding

Project overview

BAAI's multilingual embedding model: 568M parameters, 1024-dimension vectors, up to 8,192 tokens, and dense, sparse and multi-vector retrieval in one model. It covers more than 100 languages; its MIRACL benchmark includes Arabic. FlagEmbedding (github.com/FlagOpen/FlagEmbedding) is the Python library that runs it. A companion reranker, bge-reranker-v2-m3 (568M), is also available.

License: MIT for both the model and the library. Commercial use is allowed; keep the notice. Dependencies: FlagEmbedding pulls in PyTorch and transformers (about 2 GB installed). In Node, use an ONNX export through Transformers.js. Community ONNX ports exist on Hugging Face; their license and quality must be checked before use.

Integration architecture

hx-os (Next.js)                         hx-brain/wiki + hx-os/data/*.json (read-only)
  /brain page ─► /api/brain/search ─┐            │ indexer (rebuildable)
                                    ▼            ▼
              Option A: Transformers.js + BGE-M3 ONNX (in-process, Node)
              Option B: FastAPI sidecar in hx-studio  POST /api/embed  (FlagEmbedding)
                                    │
                          separate derived index (e.g. data/brain-index/*.bin)
                                    │  top-k chunks + sources
                                    ▼
              NAJM AI answer = Claude (lib/claude.ts) + retrieved Arabic/English context
  • Fits Next.js: yes. Option A keeps everything in Node and matches the documented Second Brain plan. Option B reuses the existing hx-studio Python service.
  • No database change: the vector index would be a separate file that can be deleted and rebuilt from the wiki and JSON data. The existing collections are not touched. Where the index lives still needs your approval.
  • NAJM AI: answers in both languages ("وش آخر طلبات العملاء؟"), with citations to wiki pages. The hx-team agents (sales, support) could use the same search.

Hosting and hardware

Runs on CPU. The weights are about 2.2 GB (fp32) or about 1.1 GB (fp16/int8 ONNX); plan for 3–4 GB of RAM while it runs. Indexing a few thousand wiki chunks takes minutes on a laptop CPU. No GPU is needed. The current 8 GB server is already in use, so run it on the founder's machine first.

Security and maintenance risks

  • Low. It runs offline, with no API keys and no data leaving the machine.
  • Pin the model revision and check the file hash at download; check any community ONNX port before trusting it.
  • Upstream is active (BAAI). The model is stable, so it rarely needs updating.

Estimated cost

0 AED for licensing and hosting on the existing laptop. About 4–8 hours of build effort for the POC.

Compatibility 9/10 · Accept: use it as the embedding model for the already-planned Second Brain. It is not a new system.

2 · Microsoft TRELLIS / TRELLIS.2

Project overview

Microsoft's image-to-3D generator. TRELLIS.2 (github.com/microsoft/TRELLIS.2, 4B model microsoft/TRELLIS.2-4B) turns one image into a textured mesh (GLB) and an MP4 preview. The older TRELLIS (v1) has image and text versions.

License: MIT for the code and weights. Dependency risk: the pipeline needs NVIDIA nvdiffrast (and nvdiffrec code). Their "NVIDIA Source Code License (1-Way Commercial)" appears to limit use to non-commercial purposes; see TRELLIS.2 issue #22 and the ScanCode license entry. Selling client prints made with it must not start until this is confirmed in writing or the dependency is replaced. Other dependencies: PyTorch with CUDA 12.4, xformers or flash-attn, and custom CUDA extensions.

Integration architecture

hx-studio "Image to 3D"  ──►  backends.run_external_i23d()      (already exists, no code change)
     HX_I23D_CMD='trellis-wrapper --in {image} --out {out_dir}'
                       │ runs on a separate GPU host (rented/on-demand)
                       ▼
                  mesh.glb ─► Model Doctor (diagnose/repair, 1% drift gate)
                           ─► optimizer ─► validated 3MF for Bambu P2S + AMS
                           ─► hx-slicer preview (three.js)
  • Fits Next.js: not directly; this is GPU Python. It plugs into hx-studio through the existing hook, so no HX code changes are needed.
  • NAJM AI: could prepare an image-to-print job for the founder to approve. It would also feed the hx-3d-image-to-3mf skill, which already expects a volumetric backend.
  • Overlap: the local 2.5D relief only covers single-view reliefs. TRELLIS adds a full 3D model, so this is new capability, not a duplicate.

Hosting and hardware

Officially it needs an NVIDIA GPU with 24 GB or more (tested on A100 and H100), on Linux only. Community forks claim 8–16 GB at lower resolutions; none of these are verified. It cannot run on the 8 GB CPU server or the founder's laptop unless the laptop has an RTX 4090-class card.

Estimated cost

  • On-demand cloud GPU (24–48 GB): roughly 1.5–7 AED an hour. For about 20 test jobs a month, expect about 50–150 AED a month, including start-up time.
  • Owning the hardware (24–32 GB consumer GPU workstation): about 9,000–15,000 AED one-off, plus electricity.
  • All prices are rough market estimates, not quotes.

Security and maintenance risks

  • HX_I23D_CMD runs with shell=True, so the wrapper must be a fixed script that only accepts file paths.
  • The CUDA extension stack is fragile; pin exact versions and run it in a container.
  • Generated meshes are often non-manifold or thin, so the Doctor/QC gate stays required. Do not upload client photos to a third-party GPU host unless the client agrees.

Compatibility 6/10 · Test Further: run a short trial on a rented GPU with 10 sample images through the existing pipeline. Clear up the nvdiffrast license before any commercial use.

3 · MeshRight

Project overview

github.com/Huzy85/MeshRight is a free Meshmixer-style repair tool for scans and models, made for 3D printing. It runs locally in the browser (Python backend, three.js frontend) and has a CLI (meshright check|fix|ask) and an MCP server (meshright mcp). Features: a 0–100 print-readiness score, one-click cleanup, make solid, add thickness, orientation, splitting with pins, hollowing, molds, colour 3MF for Bambu/Orca/Prusa, and point-cloud import (E57/LAS).

License: GPL-3.0; the bundled three.js is MIT. Maturity: v0.3.0, which the project calls "early alpha". The repository is 4 months old with one maintainer, 2 stars, 0 forks, and many AI-assisted commits. The last commit's CI run shows "failure".

Integration architecture

Founder's machine only (separate process, no code imported into HX):
  Claude / NAJM AI ──MCP──► meshright mcp ──► check / Clean up / export 3MF
  or: meshright check model.stl --json  ──►  report attached to the job in hx-studio
  • GPL-3.0: calling it as a separate program is fine. Copying its code into hx-studio or hx-os, or linking to it, would put HX code under GPL. Do not do that.
  • Overlap: hx-studio's Model Doctor already covers diagnose and safe repair, the optimizer covers orientation, split.py covers splitting, and the colour 3MF export already exists. MeshRight only adds things for scanned input: point clouds, scanner detection, sculpting, hollowing for resin, and molds.

Hosting and hardware

Desktop app for Windows, macOS or Linux; 8 GB RAM handles most scans and 16 GB is needed for multi-million-triangle scans. No GPU. No server needed.

Security and maintenance risks

  • The binaries are unsigned. The --host 0.0.0.0 option has no password, and anyone who can reach it can also use the stored AI key. Keep it on 127.0.0.1.
  • The project depends on one maintainer and is alpha quality, so there is a real risk it is abandoned. Pin a version.
  • Its "Ask AI" feature sends the check report (not the model) to the AI provider the user picks.

Estimated cost

0 AED. About 1–2 hours to try it on 5 real client scans and compare the results with Model Doctor.

Compatibility 6/10 · Test Further: use it only as an optional external tool for scanned input. Do not replace Model Doctor.

4 · RAGFlow

Project overview

github.com/infiniflow/ragflow is a full retrieval-augmented generation platform: it parses complex documents (PDFs, tables, scans), builds a knowledge base, adds agents and cites its sources. The latest release is v1.0.0-rc3 (30 Oct 2026), a release candidate rather than a stable release.

License: Apache-2.0, which allows commercial use. Dependencies: Docker 24.0+ and Compose 2.26.1+. The stack bundles Elasticsearch or Infinity, MySQL, MinIO and Redis/kvrocks. It can use BGE-M3 as its embedding model.

Integration architecture (if it were adopted)

hx-os /api/brain/* ──HTTP (API key, server-side only)──► RAGFlow (own server, Docker)
                                                          ├ MySQL  ├ Elasticsearch/Infinity
                                                          ├ MinIO  └ Redis/kvrocks

Hosting and hardware

Minimum 4 CPU cores, 16 GB RAM and 50 GB disk. The current 8 GB server cannot host it next to Chatwoot and the other tools, so it would need a second VPS (about 60–90 AED a month for a 16 GB Hetzner-class server).

Security and maintenance risks

  • It runs four more stateful services, each needing patching, backups and secrets. That adds a second, separate store of business data outside HX OS's JSON files and the HX Brain wiki.
  • Release-candidate status means breaking changes are still possible.

Why reject now

HX Brain (Markdown wiki) plus the planned local Second Brain already covers the need at HX's current scale. RAGFlow would be the duplicate system the brief says to avoid. Look at it again if HX needs to search hundreds of supplier PDFs, scanned invoices or datasheets with tables.

Compatibility 5/10 · Reject (look again in 6 months, or if document volume grows)

5 · FreeCAD

Project overview

github.com/FreeCAD/FreeCAD is a mature open-source parametric CAD application. The current stable release is 1.1.4 (Sept 2026); 26.3 RC2 is in testing (the version after 1.1 is called 26.3). It includes Part Design, Sketcher, TechDraw, FEM, Assembly and CAM, and can run without a screen through FreeCADCmd and Python.

License: LGPL-2.1-or-later. Using it as a separate program is safe for commercial work. Dependencies: OpenCascade, Qt, Python 3.11 and Coin3D; the install is about 1 GB.

Integration options

  • A headless worker could run FreeCADCmd scripts to make parametric parts or 2D drawings (TechDraw PDFs).
  • Overlap: hx-studio already does parametric solids with build123d, which uses the same OpenCascade kernel, and writes true B-rep STEP files. The text-to-cad skills also use build123d. FreeCAD would be a second CAD engine for the same job.
  • Genuinely new would be FEM stress checks and engineering drawings. Neither is asked for in current HX work.

Hosting and hardware

CPU only; 4–8 GB RAM is enough. As a server worker it needs a container and about 1–2 GB of disk.

Security and maintenance risks

  • Running FreeCAD macros or scripts from users would let them run arbitrary Python. Never expose it to clients.
  • Large dependency stack and a version change (1.1 to 26.3) under way.

Estimated cost

0 AED for the license. A server worker would need about 1–2 extra GB of RAM on a VPS.

Compatibility 4/10 · Reject for platform integration. The founder can still use the FreeCAD desktop app to open and edit hx-studio's STEP exports.

6 · Dify (license review only)

github.com/langgenius/dify uses the "Dify Open Source License": Apache-2.0 with two extra conditions.

  1. No multi-tenant use without written permission from LangGenius. This does not apply to uses that skip Dify's frontend. A platform serving several HX clients or agencies would need a commercial agreement.
  2. Logo and copyright must stay: you may not remove or change the Dify logo or copyright in the console or in apps built with it. This conflicts with HX's requirement for its own branding (pink #FF66B2, black and white).

It would also duplicate HX Team (4 agents), Claude skills and HX OS workflows. The hosted version is a paid subscription, and self-hosting needs about 4 vCPU and 8 GB RAM.

Compatibility 3/10 · Reject. The license restricts HX branding, and Dify would be a duplicate agent system.
